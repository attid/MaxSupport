# ADR-0001: Добавить Pyright как обязательную проверку типов

## Контекст

Контракт репозитория требует статический анализ, но до модернизации CI выполнял
только ruff. Ruff обнаруживает синтаксические и стилевые проблемы, но не
проверяет согласованность Optional-значений на границах Telegram, тикетов и БД.

Пробный запуск Pyright выявил конкретные дефекты контрактов: использование
`topic_id=None`, необработанные optional-поля aiogram и несовпадающую сигнатуру
реализации порта.

## Решение

Добавить Pyright в dev dependency group и запускать его для `src/` в стандартном
режиме на Python 3.13. Не подавлять категории ошибок глобально. Точечное
подавление допускается только для подтверждённой особенности сторонней
библиотеки с пояснением рядом с кодом.

## Последствия

- CI и `just check` будут отклонять несовместимые типы до runtime.
- Optional-значения должны явно проверяться на внешних границах.
- Обновления aiogram, Pydantic и SQLAlchemy могут потребовать локальной
  адаптации типов.
- Время локальной проверки незначительно увеличится.
